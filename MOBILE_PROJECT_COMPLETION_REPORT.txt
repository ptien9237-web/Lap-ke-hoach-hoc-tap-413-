4. Kiến trúc tổng thể:
   - Client-Server Architecture qua RESTful HTTP API JSON.
   - Offline-First with Persistent Local Storage: Client duy trì dữ liệu qua
     AsyncStorage + SecureStore. Khi mất mạng, đột biến được đẩy vào `offlineQueue`
     và đồng bộ lên endpoint `/api/sync/batch` khi khôi phục mạng.
   - Single-Source-of-Truth Theme: Toàn bộ màu sắc và khoảng cách chuẩn WCAG AA
     được quản lý trong `mobile/src/constants/theme.ts`.

5. Các giả định kỹ thuật đã dùng:
   - Backend sử dụng `node:sqlite` tích hợp sẵn trong Node 24 để bảo đảm tính di động
     cao nhất khi mang sang máy chấm bài mới (không phụ thuộc vào Visual C++ Build Tools).
   - Mạng cục bộ: Khi chạy trên Android Emulator, API client tự động chuyển hướng sang
     `http://10.0.2.2:5000`; khi chạy trên iOS Simulator / Web, dùng `http://localhost:5000`.
   - Idempotency: Mỗi mutation tạo/sửa trên mobile mang theo một UUID `clientMutationId`,
     backend lưu bảng `mutation_logs` để bỏ qua các gói tin gửi lặp.

D. API VÀ CƠ SỞ DỮ LIỆU
--------------------------------------------------------------------------------
1. Danh sách Endpoints:
   +---------------+--------+-------------------------+------------------------------------------+
   | Phương thức   | Quyền  | Đường dẫn               | Chức năng chính                          |
   +---------------+--------+-------------------------+------------------------------------------+
   | POST          | Public | /api/auth/register      | Đăng ký tài khoản sinh viên mới          |
   | POST          | Public | /api/auth/login         | Đăng nhập, trả về JWT & thông tin user   |
   | POST          | Auth   | /api/auth/logout        | Đăng xuất, ghi token vào revoked_tokens  |
   | GET           | Auth   | /api/auth/me            | Lấy thông tin user hiện tại qua JWT      |
   | GET           | Auth   | /api/courses            | Lấy danh sách học phần của sinh viên     |
   | POST          | Auth   | /api/courses            | Tạo học phần mới (code, name, colour)    |
   | PUT           | Auth   | /api/courses/:id        | Sửa học phần (bảo vệ IDOR)               |
   | DELETE        | Auth   | /api/courses/:id        | Xóa học phần và cascade bài tập          |
   | GET           | Auth   | /api/assignments        | Lấy bài tập (hỗ trợ query course, status)|
   | GET           | Auth   | /api/assignments/:id    | Lấy chi tiết bài tập (bảo vệ IDOR)       |
   | POST          | Auth   | /api/assignments        | Tạo bài tập mới                          |
   | PUT           | Auth   | /api/assignments/:id    | Cập nhật bài tập                         |
   | PATCH         | Auth   | /api/assignments/:id/st | Bật/tắt trạng thái completed/pending     |
   | DELETE        | Auth   | /api/assignments/:id    | Xóa bài tập                              |
   | GET           | Auth   | /api/stats/progress     | Thống kê tiến độ % theo từng học phần    |
   | POST          | Auth   | /api/sync/batch         | Đồng bộ batch đột biến ngoại tuyến       |
   +---------------+--------+-------------------------+------------------------------------------+

2. Cấu trúc Bảng Cơ sở dữ liệu:
   - `users`: id (TEXT PK), email (TEXT UNIQUE), password_hash (TEXT), name (TEXT), created_at (TEXT).
   - `revoked_tokens`: id (TEXT PK), token_hash (TEXT UNIQUE), user_id (TEXT), revoked_at (TEXT).
   - `courses`: id (TEXT PK), user_id (TEXT FK), code (TEXT), name (TEXT), colour (TEXT), created_at (TEXT).
   - `assignments`: id (TEXT PK), user_id (TEXT FK), course_id (TEXT FK), title (TEXT),
     due_at (TEXT ISO 8601), status (TEXT: 'pending' | 'completed'), notes (TEXT), photo_uri (TEXT), created_at (TEXT), updated_at (TEXT).
   - `mutation_logs`: id (TEXT PK), user_id (TEXT FK), client_mutation_id (TEXT UNIQUE),
     entity_type (TEXT), entity_id (TEXT), action (TEXT), synced_at (TEXT).

3. Cơ chế Bảo vệ Quyền sở hữu (Anti-IDOR):
   - Mọi câu lệnh SQL đọc hoặc ghi dữ liệu (`SELECT`, `UPDATE`, `DELETE`) bắt buộc
     có mệnh đề `WHERE user_id = ?`.
   - Khi tạo hoặc sửa bài tập, backend kiểm tra `SELECT id FROM courses WHERE id = ? AND user_id = ?`

G. BẢO MẬT VÀ DỮ LIỆU
--------------------------------------------------------------------------------
1. Lưu trữ Token bí mật:
   - Token JWT được lưu độc quyền trong phần cứng mã hóa an toàn qua `Expo SecureStore`.
   - Cấm hoàn toàn việc lưu token trong `AsyncStorage` hoặc các biến global không mã hóa.
   - Khi đăng xuất hoặc token hết hạn, `SecureStore` được dọn sạch ngay lập tức.

2. Thu hồi Token Phía Máy Chủ (Server-side Revocation):
   - Khi người dùng đăng xuất, hash SHA-256 của JWT được ghi vào bảng `revoked_tokens`.
   - Mọi request có header `Authorization: Bearer <token>` đều đi qua middleware
     `authenticateToken` để kiểm tra bảng `revoked_tokens`. Nếu token đã thu hồi,
     trả về lỗi HTTP 401 Unauthorized ngay lập tức.

3. Phòng chống Tấn công IDOR (Insecure Direct Object References):
   - Mọi truy vấn đọc/ghi đều ràng buộc với `req.user.id`.
   - Không thể can thiệp dữ liệu của người khác bằng cách đổi ID trong URL hay Body.

4. Quản lý Mật khẩu & Validation:
   - Mật khẩu được băm bằng `bcryptjs` với salt rounds chuẩn.
   - Toàn bộ payload đầu vào được validate nghiêm ngặt qua Zod schemas.

J. CHUẨN BỊ VẤN ĐÁP CÁ NHÂN (ORAL EXAM DEFENSE)
--------------------------------------------------------------------------------
1. Các module cốt lõi cần giải thích:
   - `stores/authStore.ts` & `services/secureStore.ts`: Luồng xác thực, kiểm tra session
     khi khởi động và bảo mật token bằng SecureStore.
   - `constants/theme.ts`: Kiến trúc Token màu sắc đơn nhất, không dùng hex thô trong UI,
     đảm bảo độ tương phản WCAG AA >= 4.5:1.
   - `services/offlineStorage.ts` & `syncService.ts`: Cơ chế lưu hàng đợi ngoại tuyến,
     xử lý idempotent sync qua `clientMutationId`.
   - `utils/dateUtils.ts`: Xử lý an toàn ranh giới ngày giờ, múi giờ và thời điểm 23:30/00:01.

2. Câu hỏi giảng viên có thể đặt ra và gợi ý trả lời:
   * Câu 1: "Tại sao không lưu JWT trong AsyncStorage mà phải dùng SecureStore?"
     -> Trả lời: AsyncStorage lưu trữ dưới dạng văn bản không mã hóa trong bộ nhớ máy,
     kẻ xấu có thể trích xuất nếu máy bị root/jailbreak hoặc qua backup. SecureStore
     sử dụng phần cứng bảo mật KeyStore (Android) và Keychain (iOS) mã hóa dữ liệu.

   * Câu 2: "Khi mất mạng, ứng dụng xử lý lưu bài tập và tránh trùng lặp như thế nào?"
     -> Trả lời: Bài tập được lưu tạm vào `offlineQueue` trong local storage với một mã
     UUID `clientMutationId` ngẫu nhiên. Khi có mạng trở lại, client gửi danh sách
     mutations lên `/api/sync/batch`. Backend đối chiếu `client_mutation_id` trong bảng
     `mutation_logs`; nếu đã tồn tại thì bỏ qua, nếu chưa có thì áp dụng và ghi log,
     bảo đảm tính Idempotent 100%.

   * Câu 3: "Tại sao giao diện không bị giật lag khi chuyển đổi giữa các tab?"
     -> Trả lời: Nhờ sử dụng Zustand với granular selectors (ví dụ: `useThemeStore(selectThemeMode)`),
     các component chỉ re-render khi giá trị selector thay đổi, kết hợp cơ chế cache của
     TanStack Query tránh gọi API lặp lại không cần thiết.
